# Page and documentation review checklist

Use for a local review or a future PR; this does not configure GitHub collaboration.

- Identify the module/step and intended reader; describe the visible change.
- Verify commands against the actual runtime/profile and record the checks performed.
- Separate implemented behavior, finalized future contracts, and unverified work.
- Match route/DTO/enum names, timestamps, pagination and errors to the API contract.
- Check links and diagrams against current source and migrations.
- Use synthetic examples; remove passwords, JWTs, hashes, private recipients and raw scanner output.
- For UI pages, check authorized, empty, loading, error and populated states, accessibility and responsive behavior.
- State material limitations and update only checklist items backed by evidence.
